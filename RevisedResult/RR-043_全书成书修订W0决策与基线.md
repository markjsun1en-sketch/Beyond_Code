## 1. W0 解决什么

### Observable Facts

- `OptimizedDocs/` 已有第1–23章的工作文件；第4、5章明确是非主稿对象边界接口稿。
- `PolishedDocs/` 当前只有第1、6、23章 Reader-facing 候选。
- RR-037 已冻结主要对象所有权，但独立全书复核仍发现第1、17、22章四处局部接口漂移。
- 第12章核心 Claim 已按 narrow 边界接受，但章节主轴此前没有独立 Human 裁决。
- 第17章此前为 `unsupported / unreviewed / hold`；这同时混合了概念模型能否使用、对象集是否完备和组织效果是否成立三个不同问题。
- “accepted”“pass”“pending”在 RR-038 至 RR-042 中分别指过逻辑、流程、Fidelity 或声音，不能互换。

### Assumptions

- 本书继续定位为“实践型技术专著 + 教材式导航”，而不是效果已经得到经验验证的教科书或 AI Game Dev OS 成功宣传材料。
- W0 只关闭后续成书工作的入口条件，不自动授权第12、17章 Pilot，也不自动把公开案例写入正文。

### Retrospective Inference

当前风险不是缺少更多概念，而是不同层面的状态被一个词覆盖。若不先区分逻辑、Evidence、表达、声音和连续性，后续任何“继续”都可能被错误解释为整章或全书已经接受。

### Current Recommendation

先以 W0 固定 Human 决策、修正低风险逻辑接口并建立快照；再由单独授权启动 P0。该顺序不改变 RR-037 对象模型，不把尚未完成的 Human 声音判断伪装成逻辑阻断。

## 2. W0 Human Decisions

### D-W0-01：全书承诺

**接受：** 本书提出一个可被质疑、裁剪和迁移测试的候选工程框架，并给出由具名材料支持的有限实践结论。

**不接受：** 本书已经证明 AI、Multi-Agent、Evidence-heavy Workflow、Function-first 或 Human Control Plane 普遍提高速度、质量、安全、成本、ROI 或组织效能；也不声称 AI Game Dev OS 已达到统一 Capability Level。

缺少净效果比较既不是成功证明，也不是无用证明。局部用途、项目净效果和跨项目迁移是三个不同判断。

### D-W0-02：第4、5章形态

第4章 Intent 与第5章 Context 保留为两个完整编号章节。当前接口稿继续约束对象所有权和跨章 Bridge，但不视为可直接派生成书稿的连续主稿。

后续重建必须回到原始材料恢复动机、问题和作者判断；不需要为了重建默认新增 Evidence，也不能通过合并两章重新把 Intent 与 Context 压成同一个“输入”对象。

### D-W0-03：第12章主轴

接受以下逻辑顺序：

```text
Cognitive Compression
→ Human Decision Interface
→ optional Human Control Plane organization
```

Cognitive Compression 是机制，Human Decision Interface 是面向具名决定的接口，Human Control Plane 是可选组织方式。HCP 不拥有新的 Truth 或 Authority，也没有被证明降低认知负担。

W0 接受这条主轴和当前工作稿作为 P0 的具名 Source Baseline，但不逐项冻结 Projection Contract 字段、示例、Brief 位置、HJL／TTE 归属或案例篇幅。P0 若发现实质逻辑变化，仍须先返回 `OptimizedDocs/`。

### D-W0-04：第17章模型

接受第17章的高层检查关系作为显式 Design Hypothesis。`CLM-C17-001` 收窄为：本书用 Work、Role、Assignment、Authority、Responsibility、Handoff、Conflict 与 Integration 检查协作关系；不声称这些检查面完备、最小、跨项目必要或产生组织效能。

因此该 Claim 的当前状态是 `unsupported / accepted / narrow`。`unsupported` 继续准确描述经验覆盖；`accepted` 只表示 Human 接受窄概念提案进入逻辑基线。

正文 17.3 的九个候选对象是高层假设的工作性展开，不在 W0 中逐项冻结。Subject Configuration、Dependency / Coordination 与 Responsibility 的详细映射继续由 P0 反证。

### D-W0-05：状态模型

后续不再单独使用没有限定对象的 `accepted`。每章分别记录：

```text
Logic
Evidence Route
Polish
Six Fidelity
Human Voice
Part Continuity
Book Continuity
Snapshot
```

一个轴通过不能替代另一个轴。例如，`Fidelity pass` 不等于 `Human Voice accepted`；`Logic accepted` 不等于 `Evidence verified`；`Snapshot verified` 不等于出版冻结。

## 4. Gate 模型

| Gate | 必须回答的问题 | 通过条件 | 不能替代 |
|---|---|---|---|
| G0 Decision State | Human 到底裁决了什么 | 具名 Decision、范围、日期和未接受项可见 | 逻辑或 Evidence |
| G1 Logic Baseline | 定义、前提、接口和结论是否成立 | 无未关闭的必要逻辑冲突；消费章不重夺对象所有权 | 成书声音 |
| G2 Evidence Route | 当前句子属于事实、判断、推导还是建议 | 正式 Claim 有合适 Coverage；无触发项时明确不造 Receipt | Human 审美 |
| G3 Polish Scope | 是否允许派生 Reader-facing 稿 | 具名逻辑母版、Source Map 和授权范围明确 | Fidelity pass |
| G4 Six Fidelity | 派生是否保留来源、认识论、模型、假设、案例角色与读者边界 | 六项逐章检查完成；机械检查通过 | Human Voice |
| G5 Human Voice | 是否像作者写给目标读者 | Human 对该章声音作具名判断 | 跨章连续性 |
| G6 Continuity | 章节是否能在 Part 和全书中连续工作 | 相邻接口、重复、节奏、定义首次出现和 Case 回接通过 | 最终快照 |
| G7 Snapshot | 审阅对象是否可复现 | 具名 Commit、工作树状态与未纳入项明确 | 出版决定 |

G0–G5 是逐章必要 Gate；G6 是每个 Part 与全书必要 Gate；G7 是交付必要 Gate。公开案例组合、插图和 Field Guide 只有在提供额外解释价值时才进入，不能作为 Gate 数量配额。
