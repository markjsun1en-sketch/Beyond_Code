## 建议统一的全书对象模型

后续章节应尽量都映射到以下链路，避免每章再创建功能重叠的 Object：

```text
Human / Organizational Need
        ↓
Intent Artifact                 desired outcome
        ↓
Decision / Policy               normative authority
        ↓
State Claims                    descriptive current state
Assumptions                     explicit unknowns
Evidence + Provenance           support and counterevidence
        ↓
Context View / Manifest         selected information supplied
        ↓
Execution Contract              authorized execution bundle
        ↓
Execution Epoch / Run           bounded time interval
        ↓
Change + Evidence
        ↓
Verified / Rejected State Transition
```

这里需要保持：

- Intent 不等于 Context；
- Context 不等于 Truth；
- Decision 不等于描述性事实；
- Evidence 不等于 Claim；
- Assumption 不属于 Current State；
- Execution Contract 是规范对象，Context Manifest 是实际输入记录；
- Epoch 是运行区间，不是另一个万能容器。

## 事实、推导与建议的状态

### 已有外部和实践支持

- Context 需要持续策展和压缩；
- 巨型静态说明文件容易腐化并挤占有效信息；
- Progressive Disclosure 和可恢复状态有现实价值；
- 风险治理应按组织容忍度、资源和影响调整；
- Provenance、来源责任和 derivation 是既有工程问题。

### 当前主要是本书推导

- Intent Artifact → Context → Contract → Epoch 的统一链路；
- Shared Truth, Local Context；
- Execution Epoch 作为 Agent 运行边界；
- Agent 不得自行降低 Guardrail；
- AI Game Dev OS 是生命周期驱动的 Context/State 原型。

### 尚未验证

- 这些机制是否降低错误、返工或人类认知成本；
- G0–G4 是否是合适档位；
- AI Game Dev OS 的 Context 成熟度；
- Registry/Graph/Adaptive Assembly 的收益是否高于维护成本；
- Execution Epoch 是否优于现有 Task/Sprint/Run/Transaction 术语。
