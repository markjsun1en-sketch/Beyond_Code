# RR-013：双语术语标注规范

- 记录日期：2026-08-10
- 触发对象：[第6章重构稿](../OptimizedDocs/第6章_Truth与State_Architecture_重构稿.md)
- 适用范围：全书后续工作稿
- 记录性质：写作风格裁决
- Human Disposition：`accepted`

## 裁决

不在每一次英文术语或英文声明后机械添加“（中文解释）”。

采用以下规则：

1. 核心、自创、易歧义或本书重新定义的英文术语，在第一次正式定义时附中文语义说明；
2. 中文说明应解释该术语在本书中的职责，而不只是提供字面翻译；
3. 同一术语后续重复出现时不再反复加括号；
4. 代码、Schema、路径、标识符和状态枚举保留英文，在相邻正文或表格中统一解释；
5. Git、Commit、Runtime、API、Worktree 等常见工程词不逐次翻译；
6. 值得保留的英文原则句，在第一次出现后补一条中文语义复述，不强制把解释塞进英文句子；
7. 同一术语跨章节复用同一中文解释；若章节语境改变含义，必须显式说明范围差异。

## 示例

推荐：

```text
Execution Baseline Manifest
（记录本次执行获准依赖的状态、意图、决策与显式假设）
```

不推荐：

```text
Execution Baseline Manifest（执行基线清单）
```

后者只有字面对照，没有说明对象职责。

英文原则句推荐写法：

```text
Evidence supports Claims.

证据支持或反驳主张，但不自动完成主张的授权裁决。
```

## 边界

- 第六章的全部理论主张；
- 三份 Evidence Receipt 的证据覆盖；
- 第四、第五章对象边界稿；
- 任何当前仍标为 `unreviewed` 的审阅结论。
