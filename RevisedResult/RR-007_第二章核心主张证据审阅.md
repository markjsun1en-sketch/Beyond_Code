## 待审主张

> 当 Agent 承担执行路径后，过去隐含于人类组织的信息需要逐步被显式工程化为边界、权威和证据机制。

## 核心结论

证据覆盖状态为 `partial`。lessismore 的 SP122 qualifying workflow 能够证明：在一个多 Agent、跨权威来源、需要分阶段人工裁决的任务中，显式的边界、权威、来源和证据记录确实被实际使用，并使“证据链已接受”与“可以正式采用或发布”得到区分。

现有证据不能证明：

- 所有 Agent 任务都需要同等重量的显式治理；
- Agent 是产生这些治理需求的唯一原因；
- 这些机制必然提高效率或可靠性；
- 所有过去的隐性知识都应该被文档化。

## 可观察事实

- SP122 的 Agent run plan 为不同 lane 指定了 owner、write surface、expected output、authority route 和 conflict rule。
- Evidence manifest 绑定了 producer、consumer、immutable revision、runtime evidence 和禁止性解释。
- Spec authority review 区分 active、superseded 和 conflicted 来源。
- 机器验证结果与人工 authority decision 被分开记录。
- 人工接受 qualifying evidence chain 时，仍明确阻止 supported adoption 和 production release。

## 反向证据与替代解释

- 传统人类 QA、受监管软件和跨团队交付同样会使用 manifest、provenance、gate 和 scoped approval。
- 没有同一任务“使用机制”与“不使用机制”的对照，无法建立因果效果。
- 显式治理的主要原因也可能是跨仓库交接和发布风险，而不只是 Agent 执行。
- 完整证据链仍未使项目获得正式采用，说明显式机制不是充分条件。

## 修改含义

原稿中的“必须被显式工程化”容易被理解成没有条件的普遍规律。建议收窄为：

> 当执行路径的复杂度、并发度或风险超过人类可以持续直接理解的范围时，关键边界、权威和完成证据需要按风险逐步显式化。

这个版本保留方向，但增加了触发条件和治理重量的适应性。
