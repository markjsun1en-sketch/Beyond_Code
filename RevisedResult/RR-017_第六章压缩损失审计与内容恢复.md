## 审计结论

篇幅差异不只是 Markdown 排版造成的错觉。重构稿成功修复了 Claim、State、Decision、Assumption 与 Evidence 的类型混用，但把若干工程机制从“压缩”推进到了“消失”。

因此，先前把该文件称为完整“重构稿”过于乐观。修订前版本更准确的定位是对象模型骨架稿。

结论变化来自本轮逐模块对照，而不是对原审阅标准的反转：RR-010 和 RR-012 要求删除重复概念、成熟度阶梯与类型矛盾；它们没有要求删除 Decision/Assumption 生命周期、Dirty State、Drift 和执行准备语义。

## 已恢复的四个模块

### 1. Decision 与 Assumption Lifecycle

恢复：

- Decision 的 Owner、Scope、Rationale、Options、Trade-offs、Supersedes、Review Condition 和 Expiry；
- Disposition 与 Lifecycle Status 分轴；
- Rejected Option 的否决原因与重新考虑条件；
- Assumption 的 Source、Impact、Validation、Owner、Expiry 与依赖动作；
- 风险相称的使用边界；
- Assumption 被验证或反驳后保留历史，并创建／更新有 Scope 的 State Claim。

没有恢复 `Decision Truth`，也没有恢复“Assumption 原地升级为 Truth”的类型混用。

### 2. State Boundary 与 Dirty Worktree

恢复：

- Baseline commit、branch、worktree identity 与 dirty changes；
- current-task、user/other-agent、experiment 和 unknown ownership 的差异；
- Block、Isolate、Snapshot、Declare unrelated 四类处置；
- Worktree 只能提供 Repository State Boundary，不能替代 Intent、Runtime、Authority 或 Evidence。

### 3. Drift 与 Risk-based State Readiness

恢复 Repository、Build/Deployment、Configuration、Environment 和 Data 五种 State Surface 的差异信号，并补回高风险动作开始前的 Baseline、Dirty State、Data/Config、Decision、Assumption、Recovery 与 Observation 检查。

没有恢复两个独立的 `Truth Readiness Gate` / `State Readiness Gate` 对象，而是合并为按风险启用的问题集合。失败后也不机械升级治理，而是根据当前危险选择 Block、Narrow、Revalidate、Rebase 或请求 Authority。

### 4. State Compression / Index 与 Context 边界

恢复压缩时必须保留的 Scope、Version、Condition、Expiry、Source、Conflict 和 Primary Reference，并把 State Index 收窄为导航索引。

Active Decision 与 Open Assumption 继续由 Execution Baseline 引用，不进入描述性 State Index。第五章负责选择与提供信息，第六章负责解释状态条目的类型、Authority 与 Freshness。

## Claim 与 Evidence 边界

本轮没有新增核心 Claim：

- Decision / Assumption 的类型与生命周期属于 `CLM-C06-002` 的机制展开；
- State Boundary、Drift、Baseline 与恢复环境属于 `CLM-C06-003` 的工程细化；
- Evidence Generator / Target `non-result` 继续由已接受的 `CLM-C06-004` 支持。

`CLM-C06-002` 与 `CLM-C06-003` 仍为 `partial / unreviewed`。作者同意恢复内容，不等于接受固定 Schema 能降低缺陷、返工或认知成本。

## 保留的限制

- Decision / Assumption 字段是可裁剪的示例，不是所有项目的必需 Schema；
- Dirty Worktree 处置必须结合所有权、重叠和风险，不能机械 Block；
- Data 通常具有较高不可逆风险，但并非所有数据任务都需要完整 Gate；
- Save Migration 仅是说明性场景，不作为仓库事实；
- State Index 的收益尚无前后对照证据；
- 当前内容恢复解决教学和工程语义缺口，不证明方法有效性。
